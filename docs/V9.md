# v9 — configure four voices once

Open `Bangla Toon Studio.exe`, then Settings → **Default Cartoon Voices**. There are exactly four recording selectors: Male, Female, Child Male and Child Female. There are no per-character reference controls or provider selectors on the normal Settings page.

Choose by listening: select an approved recording and use its audio player, or upload an authorized 3–30 second PCM16 WAV. Record the owner/source/permission/intended use and confirm permission for uploads. Uploaded files enter permanent managed storage and can immediately be auditioned. **Preview Bengali sample** runs local Chatterbox with that recording, before you commit the four choices. Select the four recordings you prefer and click **Save Four Voices** once. They persist across restarts. Replacing a category uses the same selector; previous files are preserved.

The app does not ship four cleared human voice recordings. At implementation time the approved local library was empty. Official demo outputs and the app's unconditioned DSP experiments remain audition-only benchmarks, not selectable production references. A category label is a user-selected role, not automatic certification of a recording's gender, age, consent or commercial rights.

## Category distribution and migration

The registered mapping is Rahat/Arif/Sami → Male; Mehna/Tithi → Female; Nabil/Rayan/Fahim → Child Male; Anika/Maliha → Child Female. Explicit narration and the off-screen voice use Male. Normal story generation validates only categories actually used. Three boys sharing Child Male produce one missing-category message, not three character prompts.

`app/voices/four_voices.py` stores schema-2 configuration in `assets/voice_references/four_voices.json`. Content-addressed authorized WAVs live under `assets/voice_references/managed/`. Configuration writes are atomic and serialized. Reference bytes, format, duration, non-silence, clipping and permission declaration are validated. Source ownership/permission is recorded, not independently certified.

On first migration, previous `profiles.json` and voice assignments are backed up under `assets/voice_references/migration-v9-backup/`. Original uploaded WAVs are never deleted. A single compatible authorized candidate can become its category's selection; multiple distinct candidates leave the category unselected for one-time listening/selection. Old paused per-character reference questions are converted into grouped category messages without automatically starting jobs. The old per-character upload endpoint now returns HTTP 410 directing callers to the four-category workflow.

## Stable, conservative variation

All ten registered characters receive persistent presets using the requested experimental offsets (0 to ±1.1 semitones). `VoiceVariationEngine` processes the original lossless speech with the installed FFmpeg Rubber Band filter, using `tempo=1`, the computed pitch ratio, `formant=preserved`, and its supported `pitchq=quality` mode. No naive sample-rate pitch shifting, EQ identity claims, denoising or speed changes are used.

The actual installed filter was queried, rather than assuming CLI flags. Output must retain the exact original sample count and rate. Unexpected duration drift or DSP clipping disables that transformation and retains the neutral original with a diagnostic; it does not silently crop or stretch speech. If formant processing is unavailable, neutral audio is retained and the limitation is recorded. Formant-preservation mode is requested from the supported processor; naturalness and perceived speaker differentiation still require listening.

Settings → **Preview Character Voices** is optional. Preview a character, compare its processed WAV with the original TTS WAV, or reset its variation. **Reset all variations to neutral** is also available. No approval is requested per character or per episode. These modest transformations do not create ten independent natural human voices.

The same section includes clearly labeled **DSP experiments** using previously generated unconditioned Chatterbox audio. They let you hear original/processed examples in the webpage without configuring production voices. They cannot be saved as cleared production references, and they are not the requested reference-conditioned four-voice listening benchmark.

## Model and caches

Chatterbox remains the default local engine. The pinned BosonLab repository revision is `025a56f71bef7fddc9ee878c9e9557d2ca559499`. The installed worker uses the Bengali-compatible toolkit loader, a 2,530-token vocabulary derived from the checkpoint, and the actual `generate(text, audio_prompt_path=...)` interface. It does not call the unrelated standard English `from_pretrained` example. The isolated runtime, CUDA attempt/one-time CPU fallback, batching and model release before Godot rendering remain.

Only dialogue and explicit narration reach synthesis. Emotion changes use only the supported modest `exaggeration` control; character pitch presets remain stable rather than changing for every emotion.

Cache A stores original model-rate PCM WAVs keyed by model/revision, reference content hash, exact synthesis text, generation settings including seed, audio format and schema version. Cache B stores transformed WAVs keyed by original speech hash, character ID, pitch/formant preset, processor/build version and output format. Changing pitch/resetting a variation reuses Cache A. Changing a category reference invalidates affected original and processed speech. Outer approved-take identities also include reference hash, category, preset and processor identity.

Original speech is additionally preserved beside each processed take as `.original.wav`. Rhubarb runs **after** transformation on the final WAV. The approved hash, cues, subtitles, Godot mouth animation and master mix all use that processed clip. Music/SFX changes reuse speech. WAV intermediates remain lossless; the final MP4 is encoded after mixing.

Auditions use the same single heavy worker as production, so they do not launch parallel model loads. Interrupted preview jobs report failure after restart rather than polling forever. Completed source/DSP caches remain reusable.

## Licensing assessment

Rubber Band's official open-source distribution is GPL, with commercial licensing offered separately. This Windows installation's existing FFmpeg reports GPL v3-or-later and exposes its Rubber Band filter. No new proprietary Rubber Band binary was bundled or proprietary redistribution clearance asserted. A proprietary packaged distribution needs a separate licensing review, appropriate commercial licensing/builds or a compatible open-source distribution. Existing FFmpeg license evidence is saved in `workspace/v9-ffmpeg-license.txt`.

## Verification and remaining acceptance work

Executed tests cover all registered mappings, persistent four-reference storage, fresh-process loading, category-only missing setup, migration conflicts/backups, stable presets, separate caches, real Rubber Band sample-count preservation, and Rhubarb reading the processed waveform. Browser tests use isolated synthetic test fixtures and a labeled TTS test double; they do not install test recordings into the production library or claim Bengali pronunciation quality.

`scripts/benchmark_v9_dsp.py` processed actual earlier Chatterbox WAVs into Nabil/Rayan/Fahim/Anika examples, rebuilt real Rhubarb cues and rendered `output/v9-dsp-evaluation.mp4`. The three boys share the same original waveform. The movie has four active speakers, exact A/V timing and unchanged audio frame counts after DSP. Its purpose is explicitly **unconditioned DSP/render evaluation**. It is not proof that four authorized base voices have been configured.

The reference-conditioned Bengali naturalness, accent, intelligibility, artifacts and voice-consistency listening benchmark remains pending your four approved selections and actual listening review. No pitch preset has been declared subjectively natural merely because automated tests pass. See `VERIFICATION.md` for the exact executed counts and artifact paths.
