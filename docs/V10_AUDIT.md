# v10 pre-change audit

The audit inspected the application/source tree, Python imports, HTTP entry points, template/script references, dependency files, asset registries, job/cache/configuration paths and existing verification artifacts. `workspace/v10-baseline-source.zip` preserves the previous source; `workspace/v10-baseline-inventory.json` records the API inventory and asset/existing-video hashes before cleanup.

Working components: the console EXE supervises a localhost FastAPI server; `/` serves vanilla chat HTML/CSS/JS; `/api/conversations` orchestrates parsing, approval-aware voice preparation and a single heavy worker. Original/processed audio caches and JSON history/configuration are persistent. Chatterbox runs in its isolated environment with the checkpoint-sized Bengali vocabulary; Rhubarb reads processed WAVs. Godot Movie Maker renders articulated cutouts by scene, FFmpeg mixes/concatenates/validates H.264/AAC outputs and probes NVENC. Shaped Bengali subtitle textures and dialogue-level times use actual WAV durations. Sound assets have local license/hash metadata and dialogue ducking.

Asset inventory: six characters are rig-ready (Rahat, Nabil, Rayan, Fahim, Anika, Maliha); Arif, Sami, Mehna and Tithi are reference-only and must not pass animation validation. Ten backgrounds are ready. Ten MP4s existed at checkpoint time. The four selected demo voices remain evaluation-only: Male 007, Female 006, Child Male 002, Child Female 005.

Confirmed cleanup candidates: `/studio` still serves an obsolete dashboard and exclusively references five legacy JS files and a separate stylesheet. Its backend production/editing APIs remain functional and will be retained; the retired screen/source can be archived and its URL redirected. The old per-character reference implementation is no longer used by voice assignment and conflicts conceptually with shared category references; only its tombstone/benchmark endpoints remain needed. `subtitle_pages` is unreferenced after the actual-WAV subtitle system replaced guessed page timing. Historical version notes dominate README and need archival, not deletion of user history.

Confirmed product gaps: Settings eagerly constructs many character/benchmark cards; the provider-status/debug detail is unnecessary. Completed cards lack regeneration. Submitted text remains in history but is not readily restored after a generation error. The normal UI hides backend error reasons even when needed. There is no explicit user-controlled disposable-file cleanup. Direct Uvicorn shutdown should release the TTS worker, not rely solely on the Windows launcher. Cancellation during default TTS waits for inference instead of stopping the worker. Optional sound files with missing/invalid bytes can stop the entire render.

Preserve: model files, all registered source art/rigs/backgrounds, reference WAVs and licensing/provenance metadata, four voice mappings and presets, usable caches, existing MP4s, conversation/job history and optional provider backends. Do not uninstall Coqui/Torch/cloud adapters merely because the normal workflow uses Chatterbox: explicit compatibility APIs still use them. No database migration, new framework, cloud service or large model is justified.

Quality limits: the existing art is a front-view cutout prototype, not newly authored TV animation; four adults lack completed rigs. Deterministic scene/emotion rules do not perfectly understand arbitrary prose. Model/DSP execution and waveform tests cannot establish natural pronunciation or commercial voice clearance; human listening review and licensing remain separate acceptance items.
