# v6 screenplay and Chatterbox upgrade

Open `Bangla Toon Studio.exe`. Its visible console shows backend logs; closing the console owns and stops the server and its child processes. Paste the story into the minimal chat, choose Generate Cartoon, then watch/download the validated MP4. Existing videos and character artwork are preserved. `/studio` remains a compatibility route for older advanced workflows; it is not part of the normal chat flow.

## Story interpretation

The first pass recognizes metadata, Bengali/English speaker labels, parenthetical delivery, bracketed sound/camera/action commands, explicit narration and screen text. A second scene-context pass maintains declared cast, previous subject and emotion, resolves sufficiently clear pronouns, and maps normalized actions to actual existing rigs. All events retain source lines. Registry/schema validation follows interpretation. Only dialogue and explicit narration reach TTS.

`mango_orchard` is a family alias for actual registered variants, ordinarily `mango_orchard_day`; no nonexistent asset is created. Small unsupported gestures use a diagnosed visual alternative or omission. Missing nonessential sounds are diagnosed and omitted. Essential unsupported actions and unknown character identities still block; they are not silently replaced. `ClarificationManager` deduplicates blocking issues. Unrecognized descriptive prose stays preserved and unspoken; deterministic rules do not provide general natural-language understanding.

The supplied regression is saved exactly in `samples/v6_regression_bn.txt`. It produces one scene, three registered characters, five spoken lines, separate gesture/music/ambience events and Bengali screen text. `idea_chime` has no suitable local asset and is omitted with a diagnostic. `funny_pop` uses a diagnosed compatible registered accent. Observation and raised-finger poses use existing thinking/raised-hand gestures; a literal box prop and new pose artwork are not authored by this parser upgrade.

Music markers change the actual soundtrack by timeline position. `fade_out` is a mixing instruction. Screen text is rendered with the existing Bengali-compatible font, with a readable hold, and is never spoken. Scene changes use the existing cuts.

## Optional AI-assisted interpretation

Settings → **Intelligent Story Understanding** defaults to **Local Rules**. No model/service is installed or called automatically. **AI Assisted** becomes available only with a configured `STORY_AI_ENDPOINT` and explicit privacy/cost consent. Configure environment variables before starting the EXE; `.env.example` is a template and is not automatically loaded.

The provider is a generic JSON endpoint implementing `app/semantic_ai.py`'s `SemanticResponse` schema. HTTPS is required except for loopback HTTP. Requests include the full story, unresolved source events and allowed registry IDs. An optional `STORY_AI_API_KEY` is sent server-side as Bearer authorization. The endpoint must return validated source-bound proposals, not executable code. Proposed identities/actions/backgrounds must exist. AI cannot invent dialogue or send an unknown instruction to TTS. Invalid responses or transport failures retain local rules and blocking issues. No external provider or local LLM has been performance-tested in this upgrade; only the interface and rejection behavior are tested.

## Chatterbox runtime

Default local provider: `BosonLab/chatterbox-bangla`, revision `025a56f71bef7fddc9ee878c9e9557d2ca559499`. The loader is `src.chatterbox_.tts.ChatterboxTTS.from_local`, from toolkit commit `2a6aba38365782fce8258a6f51708ac19c8093ce`. The loader reads the checkpoint vocabulary size (2,530), rather than using the incompatible upstream 704-token default. The temporary T3 CPU state is released before vocoder loading.

Inference runs in `.chatterbox-venv`, isolated from Coqui/VITS dependencies. This machine uses matching existing Torch/torchaudio **2.8.0+cu126** binaries through local NTFS junctions, with its own NumPy 1.26.4/Transformers 4.46.3 dependencies. A separate Torch 2.6 download timed out and is not claimed as installed. Core dependencies are pinned in `requirements-chatterbox.txt`; `workspace/chatterbox-installed.txt` records the full observed environment.

To reproduce this runtime on this Windows installation:

```powershell
.venv\Scripts\python.exe scripts\setup_chatterbox.py
```

Download the five model files from the pinned revision with `hf download`, into `models/chatterbox-bangla`. `scripts/download_chatterbox_weights.py` is the resumable HTTP fallback for stalled large transfers and verifies the two large checkpoint SHA256 hashes against pinned Hub metadata. It never imports an unrelated Chatterbox/Turbo/Nano model.

`CHATTERBOX_DEVICE=auto` attempts CUDA. A CUDA failure releases the worker completely and retries once on CPU. It never silently switches to VITS. The single app generation worker serializes heavy work; speech is unloaded before Godot/NVENC rendering. Logs include actual device and elapsed inference time; model details/errors also remain in `workspace/chatterbox-runtime.log`.

## Permanent character voices and demo evaluation

Settings contains a compact **Character reference recordings** disclosure, not another Voice Studio page. Supply a 3–30 second 16-bit PCM WAV (16–48 kHz), owner/source/license/intended-use declaration and explicit permission confirmation. The app records the declaration; it cannot certify consent. Profiles live permanently in `assets/voice_references/profiles.json`; recordings are hashed and immutable by filename. All ten registered character IDs plus narrator/off-screen roles have entries in Male, Female, Child Male or Child Female categories. An empty entry is **unconfigured**, not an invented distinct voice.

Production uses the documented `audio_prompt_path`. Missing reference permission or bytes blocks production. Different characters cannot register identical canonical PCM references. Speech caches bind speaker ID, exact normalized synthesis text, model/revision, reference SHA, settings and emotion; changing a reference cannot reuse another character's speech. VITS remains an explicit manual shared-voice option. Existing cloud choices retain their explicit payment gates.

Seven official **generated output** WAVs are stored in `evaluation/chatterbox-bangla-official/audios/output`. Settings provides local audition with the exact associated captions. The manifest includes source sample identifiers, pinned URLs, hashes and audio measurements. These files are benchmarks, never production references. See `evaluation/chatterbox-bangla-official/RIGHTS.md` for the separate Original-recording provenance investigation: commercial cloning permission is unverified, and no such clearance is claimed.

`scripts/benchmark_chatterbox.py` runs three real Bengali inference samples. `scripts/render_v6_evaluation.py` runs the supplied screenplay through real Chatterbox, Rhubarb, Godot and FFmpeg. Its output is explicitly **unconditioned evaluation only**, with the same built-in voice across characters; it does not register that voice, certify commercial rights or demonstrate distinct child voices. Human pronunciation/voice-consistency audition remains necessary. Authorized references are required for the production conditioning/consistency acceptance test.
